27  Appendix A — System Ontology v0.1 (YAML / JSON Schema)

This appendix defines a minimal machine-usable schema for representing system ontology instances within the Blueprint Architecture framework. The purpose of this schema is not to encode every possible architectural detail, but to provide a stable and extensible representation format for blueprint construction, storage, validation, and later extraction.

The schema is organized around the ontology concepts introduced in this volume:

  • entities

  • relations

  • constraints

  • views and projections

  • governance metadata

The representation is shown first in YAML instance form, then in a JSON Schema-style structural definition.

27.1 YAML Representation Template

ontology:
  id: "system-ontology-v0.1"
  version: "0.1.0"
  title: "System Ontology v0.1"
  description: "Minimal ontology schema for blueprint-based system architecture."
  status: "stable"

blueprint:
  id: "example-system"
  name: "Example System"
  ontology_version: "0.1.0"
  system_type: "web_app"
  architecture_style: "layered"
  description: "An example system ontology instance."

system:
  id: "sys.main"
  type: "System"
  name: "Example System"
  goal: "Provide a web-based interface for submitting and processing tasks."
  boundary:
    inside:
      - "comp.web_ui"
      - "comp.api_service"
      - "comp.worker"
      - "comp.db"
    interfaces:
      - "int.api.public"
      - "int.ui.web"
    outside:
      - "actor.end_user"
      - "ext.email_service"

context:
  external_entities:
    - id: "actor.end_user"
      type: "Actor"
      name: "End User"
      role: "user"
    - id: "ext.email_service"
      type: "ExternalSystem"
      name: "Email Delivery Service"

entities:
  - id: "cap.task_submission"
    type: "Capability"
    name: "Task Submission"
    description: "Allow users to submit tasks through the web interface."
    parent: null

  - id: "cap.task_processing"
    type: "Capability"

    description: "Process submitted tasks asynchronously."
    parent: null

  - id: "comp.web_ui"
    type: "Component"
    component_type: "ui"

    responsibility: "Collect user input and display results."
    inputs:
      - "user action"
    outputs:
      - "HTTP request"
    statefulness: "session_state"

  - id: "comp.api_service"
    type: "Component"
    component_type: "api_service"
    name: "API Service"
    responsibility: "Validate requests and create task records."
    inputs:
      - "HTTP request"
    outputs:
      - "task record"
      - "queue message"
    statefulness: "stateless"

  - id: "comp.worker"
    type: "Component"
    component_type: "worker"
    name: "Task Worker"
    responsibility: "Consume queued jobs and process tasks."
    inputs:
      - "queue message"
    outputs:
      - "processed result"
    statefulness: "stateless"

  - id: "comp.db"
    type: "Component"
    component_type: "storage"
    name: "Primary Database"
    responsibility: "Persist task records and results."
    inputs:

      - "read requests"

      level: "system"
      target_ref: "sys.main"

    target: "comp.web_ui"

  - type: "contains"

  - type: "contains"

  - type: "implements"

  - type: "implements"
    source: "comp.api_service"
    target: "int.api.public"

  - type: "conforms_to"
    source: "int.api.public"

  - type: "calls"
    source: "comp.web_ui"
    target: "int.api.public"

  - type: "writes"
    source: "comp.api_service"
    target: "data.task"

  - type: "emits"
    source: "comp.api_service"
    target: "comp.queue"

    source: "comp.worker"
    target: "comp.queue"

  - type: "reads"
    source: "comp.worker"
    target: "data.task"

    target: "data.task_result"

  - type: "depends_on"
    source: "comp.api_service"
    target: "comp.db"

    target: "comp.db"

    policy: "additive_first"
  deprecated: []

27.3 Minimal Entity Field Set

For interoperability across blueprint packs, Ontology v0.1 assumes a minimal required field set for all ontology entities:

minimal_entity_fields:
  required:
    - id
    - type
    - name
  recommended:
    - description

For production use, several entity classes require additional minimal fields:

entity_minimums:
  System:
    required: [id, type, name, goal]

  Capability:
    required: [id, type, name]

  Component:
    required: [id, type, name, component_type, responsibility]

  Interface:
    required: [id, type, name, interface_type]

  Contract:
    required: [id, type, name, contract_type]

  DataEntity:
    required: [id, type, name, data_kind]

  Workflow:
    required: [id, type, name]

  Trigger:
    required: [id, type, name, trigger_type]

  Constraint:
    required: [id, type, name, metric, threshold, scope]

27.4 Canonical Relation Vocabulary

The canonical relation set for v0.1 is intentionally restricted:

relation_types:
  composition:
    - contains
    - part_of

  dependency:
    - depends_on

  invocation:
    - calls
    - invokes

  event:
    - emits
    - consumes

  data:
    - reads
    - writes

  governance:
    - owns
    - governs

  contract:
    - implements
    - conforms_to

This finite set supports structural clarity, extraction feasibility, and later pattern recognition.

27.6 Extension Rule

Ontology v0.1 is designed for additive extension. Extensions should follow three rules:

extension_rules:
  - "Do not redefine core entity meanings."
  - "Prefer adding specialized attributes over changing required core fields."
  - "Introduce new entity or relation types only when existing primitives cannot express the concept without semantic distortion."

27.7 Validation Principle

A valid ontology instance under v0.1 should satisfy the following conditions:

validation_principles:
  - "Every entity must have a unique id."
  - "Every relation source and target must reference existing entities or system/context nodes."
  - "Every interface referenced by a contract relation must exist as an Interface entity."
  - "Every workflow step must reference a valid workflow."
  - "Every constraint scope must identify a valid target."
  - "The ontology_version declared in blueprint metadata must match the schema version used for validation."
